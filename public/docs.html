DOKUMENTASI GUIDE UMUM

1. Pengantar MR-CAPSULES

📖 ISTILAH PENTING (buat yang masih awam):
  • Open-source = kode dan pengelolaannya terbuka, siapa saja boleh ikut berkontribusi
  • CBT pool = kumpulan soal pilihan ganda yang bisa dipakai berulang untuk latihan/ujian
  • HTML = format file dasar halaman web; semua materi/soal di platform ini disimpan sebagai file .html

MR-CAPSULES adalah platform edukasi open-source untuk melestarikan dan mendistribusikan bahan belajar mahasiswa kedokteran/kesehatan di satu tempat. Materi kuliah, praktikum, dan soal tahun-tahun sebelumnya diubah jadi basis data HTML pilihan ganda yang bisa dipakai berulang (CBT pool).

2. Pengenalan Admin Panel

📖 ISTILAH PENTING (buat yang masih awam):
  • CBT = Computer Based Test, ujian teori lewat komputer (bukan kertas)
  • Kanban Board = papan tugas dengan kolom-kolom (Open → In Progress → Done) supaya progres kerja gampang dipantau
  • MCP = "jembatan" yang memungkinkan AI seperti Claude terhubung langsung ke Admin Panel dan menjalankan tugas otomatis
  • HTML = format file dasar halaman web; semua materi/soal di platform ini disimpan dalam bentuk file .html
  • Live Preview = fitur untuk langsung melihat tampilan file HTML tanpa perlu upload dulu

Semua kontributor bekerja lewat Admin Panel, yang punya 4 fitur utama:

  • Dashboard: Analitik aplikasi (uptime, total pengguna, member online), log aktivitas, dan papan peringkat kontributor (Leaderboard).
  • Files (File Manager): Tempat mengelola folder dan file HTML langsung. Ada HTML Editor berbasis CodeMirror dengan live preview buat ngecek materi.
  • Team (Organization): Manajemen anggota divisi, filter pengguna (Admin, Banned, Online), fitur Broadcast pengumuman, dan pengaturan global (Maintenance / Sign-up).
  • Tasks (Task Board): Papan proyek dengan sistem Kanban (Open, In Progress, Developed, In Review, Done) plus tampilan Silabus. Tugas bisa dibagi per semester dan kategori materi (CBT, OSCE, Video, Summary).

3. Pembagian Divisi Kontributor

Kontribusi di MR-CAPSULES dibagi ke beberapa divisi. Tidak perlu ragu untuk daftar — sistemnya didesain supaya gampang dipelajari siapa saja.

PENTING: Tidak perlu pengalaman coding, IT, atau organisasi untuk masuk divisi mana pun. Alur kerja teknisnya akan dijelaskan setelah kamu bergabung.

A. Management Division (Pengurus)

Menjaga kelancaran alur kerja dari Task Board sampai publikasi: assign tugas di Kanban Board, kelola pengguna di tab Team, dan menyiarkan pengumuman.

B. Development Division (Pembuat Konten)

Meracik materi mentah jadi file HTML/CBT yang interaktif. Ambil tugas di Task Board, kerjakan, lalu pindahkan ke kolom Developed (Wait for Review).

Catatan Teknis: kita tidak melakukan coding asli/manual.

Pembuatan dan perbaikan kode semuanya lewat Vibe Coding — istilah untuk men-generate kode pakai AI seperti Claude atau Antigravity. Peran developer lebih ke Prompt Engineer: menyuruh AI membuat soal dengan template yang sudah ada, lalu memasukkannya ke HTML Editor di tab Files.

C. Review & QA Division (Koreksi)

Memastikan setiap materi yang masuk kolom In Review di Task Board bebas dari typo atau konsep yang keliru.

Reviewer mengecek live preview di HTML Editor, mencocokkan kunci jawaban dengan referensi asli. Kalau lolos, tugas digeser ke Done. Kalau ada yang salah, dikembalikan ke kolom In Progress supaya Developer memperbaikinya lewat AI lagi.

MCP & API GATEWAY GUIDE

1. Integrasi MCP & API Gateway (AI Assistant Integration)

📖 ISTILAH PENTING (buat yang masih awam):
  • MCP (Model Context Protocol) = standar yang memungkinkan AI Assistant (Claude, dll) terhubung ke aplikasi lain. Cara pakainya BUKAN seperti coding atau "manggil fungsi" — Anda cukup chat/ngobrol biasa dengan Claude, lalu Claude sendiri yang otomatis menjalankan aksinya di belakang layar (mengambil task, upload file, dsb). Sama persis seperti Anda minta tolong asisten manusia, hanya saja asistennya AI yang langsung bisa "menyentuh" data di MR-CAPSULES.
  • API Gateway = pintu masuk yang mengatur lalu lintas permintaan dari luar (misalnya dari AI) ke sistem MR-CAPSULES
  • API Key = kunci rahasia berbentuk teks untuk membuktikan identitas saat AI/aplikasi luar mengakses server
  • OAuth 2.0 = metode login aman tanpa perlu membagikan password langsung ke aplikasi pihak ketiga
  • Connector = fitur di Claude.ai untuk menyambungkan Claude ke layanan luar, termasuk MR-CAPSULES
💬 INTINYA: MCP = NGOBROL, BUKAN CODING
Cukup ketik permintaan dalam bahasa biasa ke chat Claude, misalnya: "Buatkan task baru untuk materi Fisiologi Saraf blok 1.3" atau "Cek file apa saja yang ada di folder blok 2.5". Claude yang menerjemahkan permintaan itu jadi aksi teknis (memanggil tool tasks_create, content_list, dsb) di belakang layar. Tidak perlu menghafal nama tool atau menulis kode.

MR-CAPSULES menyediakan API Gateway & Model Context Protocol (MCP) serverless ganda berbasis Streamable HTTP (MCP 2025-06-18) dan OpenAPI 3.0.3 REST Actions. Lewat arsitektur ini, AI Assistant seperti Claude.ai Web, Claude Desktop, ChatGPT Custom GPTs, atau AI Agent otonom dapat berkolaborasi langsung mengelola konten, task board, dan catatan medis DoctorTablet.

A. Cara Mengoperasikan & Mengisi API Key

  1. Buka Admin Panel dan pastikan akun kamu sudah terhubung ke salah satu Divisi (Management, Development, atau Review).
  2. Pilih tab API Keys di navigasi utama.
  3. Isi nama kunci di bidang Key Name (contoh: ChatGPT Custom Connector atau Claude Web MCP) dan tentukan masa berlaku (Expires In).
  4. Klik + Generate Key. Kunci rahasia berawalan mrc_... akan muncul di kotak kuning.
  5. Klik Copy dan simpan kuncinya segera — kunci ini di-hash satu arah (SHA-256) dan tidak bisa ditampilkan ulang.

B. Menghubungkan ke Claude.ai Web (Custom Connector)

Integrasi MCP MR-CAPSULES mendukung OAuth 2.0 PKCE Auto-Discovery (RFC 8414 & RFC 7591) resmi.

  1. Buka Claude.ai → Settings → Connectors → klik Add Custom Connector (BETA).
  2. Name: isi dengan Mr Capsules.
  3. URL: isi dengan https://mr-capsules.vercel.app/api/mcp
  4. Advanced settings: biarkan kosong — otorisasi OAuth 2.0 PKCE berjalan otomatis lewat Auto-Discovery.
  5. Klik Add → Connect → masuk dengan akun Mr. Capsules kamu untuk mengotorisasi sesi.

C. Menghubungkan ke ChatGPT (Custom GPT Actions & Connectors)

ChatGPT Custom GPTs menggunakan standar OpenAPI 3.0.3 untuk memanggil fungsi eksternal secara otomatis.

⚡ OPENAI 30-ACTION LIMIT PRESET:
OpenAI membatasi maksimal 30 operasi per Action Connector. MR-CAPSULES menyediakan skema terkurasi otomatis:
  • https://mr-capsules.vercel.app/api/openapi.json?category=essential (Default ~24 Tools: DoctorTablet + Content + Tasks)
  • https://mr-capsules.vercel.app/api/openapi.json?category=doctortablet (8 Tools Khusus Vault Catatan Medis)
  • https://mr-capsules.vercel.app/api/openapi.json?category=content (12 Tools Manajemen File & Materi)
  • https://mr-capsules.vercel.app/api/openapi.json?category=tasks (14 Tools Kanban Board & QA Review)
  1. Buka ChatGPT → Explore GPTs → klik Create (atau edit Custom GPT kamu) → masuk ke tab Configure.
  2. Gulir ke bawah ke bagian Actions → klik Create new action.
  3. Pada kolom Schema, klik Import from URL → tempelkan URL skema: https://mr-capsules.vercel.app/api/openapi.json (atau pilih preset kategori di atas).
  4. Klik Import. Seluruh tools akan langsung terpetakan sebagai Action endpoints ChatGPT.
  5. Konfigurasi Autentikasi:
    • Opsi 1 - API Key (Rekomendasi Cepat): Pilih API Key → Auth Type: Bearer → Tempel API Key mrc_... yang digenerate di Admin Panel.
    • Opsi 2 - OAuth 2.0: Pilih OAuth → Auth URL: https://mr-capsules.vercel.app/authorize → Token URL: https://mr-capsules.vercel.app/token → Scope: mcp → Token Exchange: Default (POST).
  6. Privacy Policy URL: Isi dengan https://mr-capsules.vercel.app/docs#privacy.
  7. Instruksi Custom GPT (System Prompt): Salin instruksi sintesis medis DoctorTablet di bawah ini ke kolom Instructions GPT kamu.
📋 SYSTEM PROMPT DOCTORTABLET UNTUK CHATGPT & CLAUDE:
"Anda adalah Medical AI Assistant MR-CAPSULES & DoctorTablet. Saat membuat catatan medis (doctortablet_save_note): 1) Analisis & petakan struktur hirarki topik terlebih dahulu. 2) Tulis materi dengan high-density reasoning, studi kasus, & jebakan ujian (BUKAN transkrip slide PPT mentah). 3) WAJIB sertakan Callouts GitHub ([!NOTE], [!TIP], [!WARNING]), Tabel komparasi, Diagram Mermaid, dan Rumus Matematika/Skor Medis dalam format LaTeX ($...$ / $$...$$). 4) Parameter author WAJIB nama lengkap pengguna tanpa gelar akademis."

D. Menghubungkan ke Google Antigravity (Agent & IDE Connector)

Google Antigravity dapat terhubung langsung ke MR-CAPSULES melalui server Streamable HTTP MCP atau OAuth 2.0 PKCE Flow.

  1. Opsi 1 - Konfigurasi Streamable HTTP MCP (Direkomendasikan untuk Agen):

    Tambahkan konfigurasi berikut ke berkas konfigurasi MCP Antigravity (mcp.json atau settings.json):

    {
  "mcpServers": {
    "mr-capsules": {
      "url": "https://mr-capsules.vercel.app/api/mcp",
      "headers": {
        "x-api-key": "mrc_your_api_key_here"
      }
    }
  }
}
  2. Opsi 2 - Otorisasi OAuth 2.0 PKCE Langsung:

    Antigravity mendukung otorisasi OAuth 2.0 native dengan skema pengalihan kustom (antigravity://oauth/callback):

    • Authorization URL: https://mr-capsules.vercel.app/authorize?client_id=antigravity-mcp&redirect_uri=antigravity://oauth/callback&response_type=code
    • Token URL: https://mr-capsules.vercel.app/token
    • One-Click Connect: Jika browser Anda sudah memiliki sesi login aktif di MR-CAPSULES, halaman otorisasi otomatis menyembunyikan formulir dan menampilkan tombol 1-klik "Approve & Connect as [email]".
CATATAN PENGGUNAAN: API Key dibatasi maksimum 5 kunci aktif per pengguna, dengan rate limit 60 request/menit untuk mencegah penyalahgunaan.

A. Level Akses (Role Hierarchy)

  • SuperAdmin: Pemegang kendali penuh sistem & codebase. Satu-satunya yang dapat mengedit file codebase backend/frontend, mengangkat/menurunkan Admin, dan menghapus akun secara permanen.
  • Admin: Diangkat oleh SuperAdmin. Mengelola konfigurasi sistem, konten, dan moderasi pengguna, namun tidak bisa mengubah hak Admin lain.
  • Reviewer: Anggota Divisi Review & QA. Berwenang atas siklus review tugas (start review, approve, reject, lapor isu).
  • Developer: Anggota Divisi Development. Berwenang mengambil (claim) dan mengumpulkan (submit) tugas.
  • Semua Pengguna Terautentikasi: Akses baca umum serta pengelolaan data milik sendiri (API key, kontribusi, WhatsApp, dsb).

3. Privacy Policy & Data Protection

MR-CAPSULES Platform berkomitmen penuh untuk menjaga keamanan, privasi data pengguna, dan integritas materi edukasi kedokteran:

  • Zero Data Sale: Kami tidak pernah menjual, menyewakan, atau memperdagangkan data pribadi pengguna kepada pihak ketiga manapun.
  • Autentikasi & Enkripsi: Seluruh komunikasi data dilindungi melalui enkripsi SSL/TLS (HTTPS). Kunci API dan token OAuth di-hash satu arah menggunakan SHA-256 dengan siklus masa kedaluwarsa ketat.
  • Akses AI Assistant: AI Assistant (ChatGPT Custom GPT, Claude MCP) hanya dapat mengakses data dan menjalankan perintah sesuai dengan hak akses (role) pengguna yang terotentikasi. Data percakapan diproses secara langsung antara klien AI dan gateway serverless tanpa penyimpanan histori di luar audit log operasional.
  • Penghapusan Data: Pengguna dapat mencabut kunci API atau memutuskan sesi OAuth kapan saja melalui Admin Panel.
MANAGEMENT DIVISION GUIDE

1. Mengidentifikasi Konten yang Dibutuhkan per Blok

📖 ISTILAH PENTING (buat yang masih awam):
  • Gap konten = materi yang seharusnya ada di silabus tapi belum tersedia file HTML-nya di platform
  • Silabus = daftar resmi kuliah/praktikum dari program studi untuk satu blok
  • Template Lecture = format file HTML berisi rangkuman materi kuliah + kuis (lihat detail lengkap di tab Development Division)
  • Template CBT / Quiz Engine = format file HTML khusus soal ujian murni tanpa rangkuman materi, dengan mode Study/Exam/Drill (lihat detail lengkap di tab Development Division)
  • Task duplikat = dua task berbeda yang ternyata membahas topik yang sama, sehingga membuang waktu Developer
  • MCP = cara menghubungkan Claude ke MR-CAPSULES. Penggunaannya seperti chat biasa, bukan menulis kode — Anda cukup minta ke Claude dalam bahasa sehari-hari, Claude yang menjalankan aksinya

Tugas pertama Management adalah memetakan gap antara materi yang sudah ada di platform dan yang seharusnya ada — dilakukan sebelum task apapun dibuat.

A. Langkah Audit Konten

  1. Buka tab Files di Admin Panel → navigasi ke folder blok yang mau diaudit (contoh: content/semester 2/2.5/).
  2. Bandingkan file yang ada dengan silabus blok (daftar kuliah/praktikum resmi dari prodi). Catat materi yang belum punya file HTML.
  3. Cek tab Tasks di Kanban Board — pastikan materi yang belum ada itu belum punya task aktif (Open / In Progress / In Review), supaya tidak dobel assignment.

B. Jenis Konten HTML yang Dibutuhkan

Semua konten di MR-CAPSULES berbentuk file .html interaktif. Sesuai penjelasan lengkap di tab Development Division, ada dua jenis template, tergantung sumber materinya:

Fitur / Karakteristik Template HTML Lecture Template HTML CBT
Dipakai untuk task Materi kuliah teori & modul praktikum yang belum pernah dirangkum Naskah soal ujian CBT tahun lalu / bank soal siap pakai
Sumber Utama PPT Kuliah / Modul Praktikum Naskah Soal CBT Tahun Lalu / Bank Soal
Elemen Utama Tab 📋 Materi (Rangkuman) + Tab 🎯 Quiz Pure Engine Kuis (Study, Exam, Drill Mode)
Penyajian Materi Sub-tabs, Note boxes, Data tables, Diagram SVG Tidak ada (hanya lewat penjelasan di kuis)
CATATAN UNTUK MANAGEMENT: Saat membuat task (lihat Section 2), tentukan dulu sumbernya: materi kuliah/praktikum baru (→ Template Lecture) atau naskah soal ujian siap pakai (→ Template CBT). Ini membantu Developer langsung tahu template mana yang harus dipakai tanpa perlu tanya lagi.

C. Aturan Prioritas Sumber: PPT Lecture vs. Modul Praktikum

Kalau untuk satu topik yang sama ada dua sumber (PPT lecture dan modul praktikum), ikuti hierarki berikut:

ATURAN EMAS: Pilih satu sumber yang paling lengkap — jangan buat dua file HTML terpisah untuk materi yang identik. Tujuannya menghindari duplikasi konten yang bikin bingung pengguna.
KondisiSumber yang DipakaiAlasan

Konten benar-benar sama persis (PPT = ringkasan modul) Pakai modul praktikum, abaikan PPT Hindari duplikasi; modul lebih terstruktur untuk dijadikan materi + soal

D. Cara Mengecek Kelengkapan via Files

  1. Di tab Files, buka folder blok target.
  2. Klik kanan (atau ikon titik tiga) pada file HTML yang ada → pilih Edit Code → pakai Live Preview untuk cepat lihat isinya.
  3. Kalau file yang ada sudah mencakup materi dari PPT dan modul secara memadai, tidak perlu task baru. Kalau belum lengkap, catat untuk dibuatkan task revisi.

2. Menginput Task ke Task Board

Setelah audit selesai dan daftar gap konten tersusun, langkah berikutnya adalah membuat task di Kanban Board. Ada dua cara: manual via Admin Panel, atau chat ke AI via MCP (Claude.ai / Antigravity).

A. Cara Manual (via Admin Panel)

  1. Buka tab Tasks di Admin Panel.
  2. Klik + Create Task (tombol ini hanya muncul untuk akun Management/Admin).
  3. Isi form dengan ketentuan berikut:
    • Title: Nama materi spesifik, jelas, dan konsisten. Format yang direkomendasikan: [Mata Kuliah] [Topik] — [Tipe]
      Contoh: Fisiologi Saraf Otonom — CBT atau Histologi Epitel — Identifikasi
    • Semester: Pilih semester yang sesuai (contoh: semester 2).
    • Block: Isi nomor blok (contoh: 2.5). Wajib diisi agar task muncul di tampilan Silabus.
    • Category: Isi sesuai peruntukan ujian: CBT untuk soal teori, atau nama blok/kategori custom (misal Praktikum Fisio). Field ini bebas diisi — gunakan nama yang konsisten biar gampang difilter di Kanban Board.
    • Priority: Sesuaikan urgensi:
      • urgent — ujian < 2 minggu lagi
      • high — ujian 2–4 minggu
      • normal — standar
      • low — cadangan / tidak mendesak
    • Description: Cantumkan detail sumber materi, misalnya: “Buat soal CBT dari PPT K10 am-i-counseling. Fokus pada prinsip dasar konseling dan hambatan komunikasi. Target ~20 soal.”
    • Target Path (opsional): Kalau sudah tahu path file tujuan, isi di sini (contoh: content/semester 2/2.5/2.5 CBT_K10 am-i-counseling.html) — memudahkan Developer tahu di mana menyimpan hasil kerjanya.
    • Assign To (opsional): Pilih Developer tertentu dari dropdown kalau mau mendelegasikan langsung. Kosongkan kalau mau open claim.
  4. Klik Confirm. Task akan muncul di kolom Open pada Kanban Board.
TIPS: Dari tab Files, kamu bisa klik kanan file yang sudah ada → Create Task untuk pre-fill otomatis Target Path dan langsung buka form task. Jauh lebih cepat daripada input manual satu per satu.

3. Memastikan Developer & Reviewer Tidak Redundan

Redundansi terjadi ketika satu anggota mengerjakan sekaligus mereview konten miliknya sendiri, atau ketika dua Developer membuat file untuk topik yang sama. Ini harus dicegah secara sistematis.

A. Prinsip Pemisahan Peran

  • Developer hanya boleh mengerjakan (claim) dan mengumpulkan (submit) task. Mereka tidak boleh mereview hasil kerja sendiri.
  • Reviewer hanya boleh mereview task yang bukan miliknya. Kalau seorang anggota merangkap Developer & Reviewer, Management harus memastikan dia tidak ditempatkan di tugas yang sama.
  • Management (Admin/SuperAdmin) boleh memantau semua alur, tapi sebaiknya tidak terlibat langsung dalam produksi konten supaya bisa bertindak netral saat eskalasi.

B. Langkah Pencegahan Redundansi Developer

  1. Sebelum membuat task: cek di Kanban Board (kolom Open, In Progress) apakah topik sudah ada task-nya. Pakai filter atau search di tab Tasks.
  2. Saat assign task: kalau assign langsung lewat form (bukan open claim), pastikan tidak ada dua task dengan topik identik yang di-assign ke Developer yang sama.
  3. Kalau dua Developer tidak sengaja mengklaim topik yang sama: Management pakai tasks_delete pada task duplikat, atau tambahkan note lewat tasks_add_note untuk mengarahkan Developer kedua ke topik lain.
  4. Pantau kolom Developed (Wait for Review): kalau ada dua file masuk untuk topik yang sama, Management menentukan mana yang lebih lengkap, lalu reject yang lebih lemah dengan catatan (lewat Reviewer).

C. Langkah Pencegahan Redundansi Reviewer

  1. Saat task masuk kolom In Review, Reviewer yang mengklaim tidak boleh sama dengan Developer yang mengerjakan task itu. Cek nama di log task (tasks_logs) sebelum mulai review.
  2. Kalau tim kecil dan tidak ada Reviewer lain yang tersedia, eskalasi ke Management — Management yang melakukan review sementara, atau tunda task sampai Reviewer tersedia.
  3. Gunakan field Note (tasks_add_note) untuk mendokumentasikan siapa yang sudah mereview sesi mana, terutama pada materi besar yang direview bertahap.

D. Monitoring via Kanban Board & Leaderboard

SinyalApa yang Harus Dilakukan Management
Satu Developer dominasi kolom In Progress (>5 task sekaligus) Batasi claim — tambahkan note di task agar Developer fokus menyelesaikan yang ada dulu
Tidak ada aktivitas di kolom In Review >3 hari Ping Reviewer via Broadcast (tab Team) atau tambahkan note urgency
Task di kolom Open sudah lama tidak diklaim Assign langsung ke Developer via form edit task, atau naikkan priority ke urgent
Satu anggota top Leaderboard tapi seluruh task belum Done Cek apakah ada task yang stagnan di In Review — review pipeline mungkin macet

E. Checklist Harian Management

  • Buka Kanban Board → pastikan tidak ada task yang stuck lebih dari 48 jam di satu kolom.
  • Cek Dashboard → Activity Log untuk mendeteksi aksi tak wajar (misal: submit tanpa claim, atau approve oleh Developer).
  • Review kolom Done mingguan → pastikan file HTML-nya benar-benar ada di tab Files (path sesuai).
  • Bandingkan jumlah task Done vs task Open untuk ukuran produktivitas divisi secara keseluruhan.

2. Memahami 2 Jenis Template HTML & Perbedaannya

Di MR-CAPSULES (khususnya standar Blok 2.5 FK), ada dua jenis template HTML utama. Developer perlu memilih template yang tepat sesuai jenis task yang diklaim.

A. Template HTML Lecture (Materi & Quiz)

Dipakai saat membuat file dari PPT Lecture atau Modul Praktikum. Contoh file acuan: 2.5 LECTURE_K10 am-i-counseling.html.

  • Struktur 2 Tab Utama: Terdiri dari tab 📋 Materi dan tab 🎯 Quiz di bagian atas.
  • Bagian Materi (Interaktif):
    • Materi dipecah menjadi beberapa Sub-Tabs per bab/topik.
    • Memiliki elemen Note Box berwarna (gold, blue, green, red, purp, teal) untuk poin-poin penting.
    • Memiliki Data Tables (dtable-wrap) untuk klasifikasi, dosis, atau kriteria diagnostik.
    • Mendukung diagram/flowchart SVG interaktif (misalnya alur komunikasi atau skema patofisiologi).
  • Bagian Quiz: Menyediakan kuis interaktif dengan pilihan ganda dan pembahasan langsung di tempat untuk menguji pemahaman materi kuliah tersebut.
  • Desain & Tipografi: Menggunakan variabel CSS modern dengan kombinasi font Google Fonts: Syne (Header), DM Sans (Body), dan DM Mono (Code/Data).

B. Template HTML CBT / Soal Ujian (Pure Quiz Engine)

Dipakai khusus saat memasukkan Naskah Soal Ujian Tahun Lalu atau bank soal ujian murni. Contoh file acuan: 2.5 CBT_21 REECHARD GANTENG.html.

  • Tanpa Tab Materi: Berisi 100% engine kuis tanpa penyajian rangkuman kuliah di depannya.
  • 3 Mode Belajar Utama:
    • Study Mode: Menampilkan kunci dan pembahasan komprehensif segera setelah memilih opsi.
    • Exam Mode: Simulasi ujian terwaktu, jawaban tersembunyi hingga kumpul ujian, dilengkapi modal konfirmasi.
    • Drill Mode: Mode pengulangan tanpa skor — pengguna harus memilih opsi yang benar untuk maju.
  • Fitur Ujian Lengkap: Question Map (peta nomor), penanda soal (flag 🏳️), statistik & riwayat skor lokal (localStorage), serta analisis akurasi per topik.
  • Struktur Data JS: Soal disimpan dalam array JavaScript utuh di bagian bawah file:
    const QUESTIONS = [{n:1, t:"Topik", q:"Pertanyaan...", o:["A","B","C","D","E"], a:"Kunci Jawaban", exp:"Pembahasan...", src:"Sumber"}, ...];
  • Desain & Tipografi: Menggunakan gaya retro-minimalist yang bersih dengan font Georgia untuk judul dan Courier New untuk elemen data.

Formulasi Prompt Resmi (Copy & Paste ke AI):

Pahami seluruh struktur, CSS, dan skrip JavaScript dari file template HTML Lecture yang saya berikan.

Tugasmu adalah membuat file HTML lengkap baru berdasarkan materi kuliah/modul yang saya unggah ini, dengan ketentuan berikut:

3. JUDUL DAN AKSEN WARNA KUSTOM:
   - Berikan judul yang sesuai dan menarik di bagian header (contoh: "Am I Counseling? — Quiz Keterampilan Dasar Konseling").

B. Prompt untuk Soal CBT Tahun Kemarin (Template CBT)

Gunakan prompt ini ketika Anda mengunggah file Template HTML CBT dan naskah/dokumen Soal Ujian CBT Tahun Lalu ke AI.

Formulasi Prompt Resmi (Copy & Paste ke AI):

Pahami seluruh engine kuis, struktur CSS, dan array JavaScript `QUESTIONS` dari file template HTML CBT yang saya berikan.

Tugasmu adalah menyajikan seluruh naskah soal ujian ini ke dalam template HTML CBT tersebut, dengan ketentuan berikut:

1. PRESERVASI KELENGKAPAN SOAL:
   Sajikan TEPAT [masukkan jumlah soal, misal: 105] SOAL dari naskah ini ke dalam array `QUESTIONS`. JANGAN SAMPAI ADA SATU PUN SOAL, OPSI JAWABAN, ATAU NOMOR YANG TERLEWAT ATAU DIPOTONG.

2. FORMULASI ARRAY QUESTIONS:
   Setiap objek soal harus memiliki struktur:
   - `n`: Nomor urut soal (1, 2, 3, dst.)
   - `t`: Nama topik/sub-materi singkat (misal: "Fisiologi Saraf", "Farmakologi", "Gizi Daur Hidup")
   - `q`: Teks pertanyaan lengkap (sertakan kasus/vignette jika ada)
   - `o`: Array 5 pilihan jawaban `["A", "B", "C", "D", "E"]`
   - `a`: Teks string kunci jawaban yang BENAR (harus persis sama dengan salah satu opsi di `o`)
   - `exp`: Pembahasan lengkap dan rinci mengapa jawaban tersebut benar dan mengapa opsi lain kurang tepat, berdasarkan teori medis di PPT/Modul.
   - `src`: Referensi slide/PPT (contoh: "PPT Merokok dan Alkoholisme — dr. Yudhi")

3. JUDUL DAN AKSEN WARNA:
   - Sesuaikan bagian `.logo-wordmark` dan `.logo-tag` di header (contoh: "21 PILL SAPI", Blok "2.5").
   - Atur warna aksen visual yang sesuai di CSS :root.

Keluarkan seluruh kode HTML utuh tanpa potongan agar siap saya simpan langsung ke file .html.

REVIEW & QA DIVISION GUIDE

1. Peran & Tanggung Jawab Divisi Review

PRINSIP DASAR REVIEW:
Divisi Review bertugas memastikan setiap file HTML yang masuk dari Developer akurat secara konten medis sebelum dipublikasikan. Satu soal yang salah kunci atau penjelasannya menyesatkan lebih berbahaya daripada tidak ada konten sama sekali.

A. Apa yang Diperiksa oleh Reviewer?

  • Kunci Jawaban: Pastikan field a (answer) dalam setiap soal benar-benar merupakan opsi yang paling tepat secara medis.
  • Pembahasan (Explanation): Pastikan field exp menjelaskan mengapa jawaban benar dan mengapa opsi lain salah secara ilmiah — bukan hanya menyebutkan ulang jawabannya.
  • Referensi Sumber: Pastikan field src mencantumkan PPT atau modul yang relevan dan benar.
  • Konsistensi Opsi: Kunci jawaban di field a harus persis sama (karakter demi karakter) dengan salah satu opsi di array o — jika tidak cocok, soal akan tidak berfungsi.
  • Tata Bahasa & Ejaan: Tidak ada typo, kalimat ambigu, atau istilah medis yang keliru penulisannya.

B. Aturan Pemisahan Peran (Anti-Redundansi)

ATURAN WAJIB: Developer dan Reviewer untuk satu task yang sama TIDAK BOLEH orang yang sama. Tujuannya adalah memastikan ada perspektif kedua yang independen dalam proses QA. Jika tidak ada Reviewer lain yang tersedia, eskalasikan ke Management untuk reassignment.

2. Dua Jalur Koreksi

Saat Reviewer menemukan kesalahan pada file HTML, tersedia dua jalur tindakan tergantung jenis dan skala kesalahannya:

Jalur Kapan Digunakan Cara Kerja
Jalur A — Patch Langsung via MCP Kesalahan spesifik dan terisolasi: satu soal salah kunci, satu pembahasan keliru, typo pada penjelasan, atau referensi sumber salah nama Reviewer chat ke Claude/Antigravity → Claude langsung patch file HTML di server via MCP
Jalur B — Eskalasi ke Development Kesalahan struktural / masif: >30% soal salah, template HTML rusak, urutan soal kacau, atau soal tidak sesuai materi sama sekali Reviewer hubungi Developer via catatan task atau Broadcast → Developer revisi file ulang → kembali ke Review

3. Jalur A — Patch Langsung via MCP (Claude Connector)

Ini adalah jalur tercepat untuk memperbaiki kesalahan minor tanpa harus melibatkan Developer. Reviewer cukup chat ke Claude.ai (dengan MCP MR-CAPSULES aktif) atau Antigravity CLI.

SELURUH PROSES PATCH BISA DILAKUKAN MURNI VIA CLAUDE CONNECTOR
Tidak perlu membuka code editor, tidak perlu tahu cara edit HTML. Cukup chat ke Claude dengan informasi yang jelas — Claude yang akan membaca file, menemukan soal yang dimaksud, dan memperbaikinya langsung di server.

A. Format Permintaan Patch ke Claude

Gunakan format percakapan natural berikut. Semakin spesifik informasi yang Anda berikan, semakin akurat hasilnya:

Template Permintaan Patch (Sesuaikan dengan kasus Anda):

"Di file [nama file atau path lengkap, misal: content/semester 2/2.5/2.5 CBT_21 REECHARD GANTENG.html],

[Tulis pembahasan baru di sini — jelaskan mengapa jawaban benar dan mengapa opsi lain kurang tepat]

Tolong perbaiki soal tersebut di file HTML-nya langsung."

Contoh 1 — Salah Kunci Jawaban:

C. Apa yang Dilakukan Claude Setelah Menerima Permintaan?

  1. Claude membaca file HTML yang dimaksud via MCP tool content_get.
  2. Claude menemukan soal dengan nomor yang disebutkan dalam array QUESTIONS.
  3. Claude memperbarui field yang salah: a (kunci), exp (explanation), dan/atau src (referensi).
  4. Claude menyimpan perubahan kembali ke server via MCP tool content_upload atau content_patch.
  5. Claude melaporkan perubahan yang telah dilakukan untuk dikonfirmasi Reviewer.
TIPS REVIEWER: Setelah Claude selesai patch, minta Claude menampilkan soal yang sudah diperbaiki untuk verifikasi akhir sebelum mengubah status task. Contoh: "Tampilkan soal nomor 25 yang sudah diperbaiki dari file tersebut".

Gunakan jalur ini jika masalah yang ditemukan terlalu besar atau terlalu struktural untuk dipatch satu per satu.

B. Cara Mengeskalasi ke Developer

  1. Via Catatan Task di Admin Panel:
    • Buka task yang bersangkutan di Kanban Board → klik Add Note / Comment.
    • Tulis catatan spesifik tentang apa yang perlu diperbaiki dan alasannya.
    • Ubah status task kembali ke In Progress (atau biarkan di In Review dengan catatan) agar Developer tahu ada pekerjaan yang perlu direvisi.
  2. Via Chat ke Claude (MCP):
    • Minta Claude menambahkan catatan ke task: "Tambahkan catatan ke task [ID/nama task]: File perlu direvisi karena [alasan]. Mohon Developer mengerjakan ulang bagian [spesifikasi]."
    • Atau minta Claude mengubah status task kembali: "Set status task ini kembali ke In Progress dan tambahkan note bahwa perlu revisi ulang."
  3. Via Broadcast (Tab Team):
    • Gunakan fitur Broadcast di tab Team untuk mengirim pesan ke Developer yang bersangkutan jika perlu komunikasi langsung dan mendesak.
